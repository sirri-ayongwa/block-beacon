BlockBeacon Firestore rules analysis

Collections identified from Supabase types/migrations and current app calls:
- profiles: id, display_name, country, default_anonymous, digest_subscribed, digest_last_sent_at, home_lat, home_lng, home_zoom, preferred_language.
- issues: id, reporter_id, title, description, category, lat, lng, status, anonymous/photo/handoff fields, upvote_count, timestamps.
- issue_votes: issue_id, user_id, created_at.
- issue_photos: issue_id, path, created_at.
- issue_status_events: issue_id, status, note, created_by, created_at.
- moderator_profiles: id, community, gov_email, organization, proof fields, verified, AI review fields.
- user_roles: user_id, role. Privileged collection; client reads only.
- issue_comments: issue_id, user_id, body, is_moderator.
- chat_rooms: issue_id, title, created_by, expires_at.
- chat_messages: room_id, user_id, body.
- notifications: user_id, kind, title, body, issue_id, image_path, read_at.

Queries identified:
- profiles by id, in id list, country reads.
- issues list ordered by upvote_count or created_at; issue by id; updates by id.
- issue_votes by issue_id/user_id and ordered by created_at.
- issue_photos by issue_id ordered by created_at.
- issue_status_events by issue_id ordered by created_at.
- moderator_profiles by id and by in id list.
- user_roles by user_id and role.
- comments/messages/notifications by foreign key and created_at.

Rules posture:
- Default deny.
- Auth required for all app data reads.
- Owner-only writes for profiles, votes, comments, chat messages, notifications, and moderator applications.
- Role documents are read-only to clients to prevent self-granting.
- Moderator issue updates depend on existing user_roles documents.
- Validators enforce allowed fields, required fields, string lengths, enum values, and owner IDs.

Devil's advocate notes:
- Public unauthenticated reads are denied.
- Users cannot create user_roles, so direct privilege escalation is blocked.
- Owner ID fields are validated on create and constrained by owner checks.
- Oversized strings are blocked by explicit length limits on user-writable text fields.
- Some privileged automation previously handled by Supabase triggers, such as vote counters and notifications, is not fully reproduced in rules; app-side compatibility currently writes basic documents only.
